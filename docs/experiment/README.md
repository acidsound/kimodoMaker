# Kimodo 한국어 텍스트 인코더 교체 실험

**목표**는 Windows 11·RTX 4090 24GB에서 `google/embeddinggemma-2`의 텍스트 인코더와 학습한 어댑터만으로 한국어·영어 프롬프트를 Kimodo 모션으로 변환하는 것이다. 원본 Kimodo의 영어 지시 이행률과 동작 품질을 기준으로 비교한다. 아래 수치는 실험 시작 전에 제안한 **v1 인수 기준**이다. 달성 여부는 미측정이다.

기계 판정식은 [EncoderTrial.tla](EncoderTrial.tla)의 `Gate`, 반복·종료 규칙은 `Evaluate`와 `Confirm`에 있다. 표와 구현이 다르면 실행을 중단하고 명세 버전을 맞춘다. 모델 체크와 실제 GPU 실험은 각각 별도의 결과로 기록한다.

## 1. 비교 조건과 완료 기준

| 조건 | 문장 | Kimodo에 전달할 표현 |
| --- | --- | --- |
| ref | 영어 원문 | 공식 LLM2Vec의 4096차원 출력 |
| en | 동일 영어 원문 | EmbeddingGemma 2 텍스트 모드 + 어댑터 |
| ko | 같은 뜻의 한국어 | en과 동일한 체크포인트 및 전처리 |

각 세트에는 동작 유형 4개 × 유형당 지시 16개 × 시드 3개가 있다. 조건당 192클립이다. 세 조건에 같은 프롬프트 ID, 시드, 길이, 스텝, Kimodo 가중치와 후처리를 사용한다. 학습된 모델을 배포 후보로 인정하려면 개발·최종 시험에서 각각 아래 모든 조건을 충족해야 한다. 퍼센트는 반올림 전 값으로 비교한다.

| 판정 | 합격선 |
| --- | --- |
| 전체 지시 이행 | en과 ko 각각 80% 이상(192개 중 154개 이상). 각각 ref보다 최대 5%p 낮을 수 있다(9개 차이까지). |
| 유형별 이행 | en과 ko의 네 유형 각각 70% 이상(48개 중 34개 이상). 같은 유형의 ref보다 최대 10%p 낮을 수 있다(4개 차이까지). |
| 언어 간 차이 | en과 ko 전체 성공률의 절대 차이 5%p 이하 |
| 모션 품질 | en과 ko 각각 아래 운동학 검사 통과율 90% 이상(173개 이상). 각각 ref 대비 하락 5%p 이내 |
| 자원 | en과 ko 각각 전체 생성 경로의 최대 GPU 메모리 ≤ ref의 80%. 요청 지연 p95 ≤ ref의 120% |
| 실행·산출물 | Llama 가중치가 없는 후보 환경에서 새 프롬프트로 실제 생성. 앱에서 VRM 재생과 JSON/BVH/NPZ 내보내기 검증. 아래 증거 요건 충족 |

ref에도 같은 검사를 적용한다. ref 자체가 어려워하는 지시에서 원본 수준에 도달해도 후보의 절대 하한은 그대로 적용한다. 이 기준은 고정 평가 세트에 대한 인수 시험이다. 일반 한국어 전체에 대한 통계적 비열등성으로 해석하려면 별도의 표본 설계가 필요하다.

판정의 최상위 식은 다음과 같다. `Valid`는 레코드의 수치 범위와 자료형을 검사한다. `Students = {"en","ko"}`이며 각 술어의 정수 부등식은 동봉한 모듈에서 실행할 수 있다.

```tla
Gate(m) ==
  /\ Valid(m) /\ m.evidence /\ m.standalone /\ m.exports
  /\ LanguageGap(m)
  /\ \A a \in Students : Intent(m,a) /\ Quality(m,a) /\ Cost(m,a)
```

## 2. 데이터와 평가 세트 동결

- 사용 권한이 있는 BONES-STUDIO 모션 캡션과 프로젝트용 지시를 수집한다. 영어와 한국어는 동작 주체, 신체 좌우, 방향, 순서, 속성까지 대조한다. 원본 ID, 반전본, 같은 클립의 모든 캡션·번역·바꿔쓴 문장, 같은 최소 대립쌍을 하나의 그룹으로 묶는다. 학습·개발·시험 사이에 같은 그룹이 있으면 분할을 다시 만든다. 각 평가 세트에는 학습에서 보지 않은 동작 조합을 넣고 해당 ID를 표시한다. [BONES-SEED 캡션](https://huggingface.co/datasets/bones-studio/seed)
- 개발과 최종 시험에 각각 유형당 최소 대립쌍 8개를 준비한다. 한 쌍은 한 가지 지시만 바꾼 두 문장이다. 유형은 ① 왼손/오른손 ② 좌회전/우회전 ③ 두 행동의 순서 ④ 자세 높이 변화로 고정한다. 각 항목에는 영·한 문장, 동작별 성공 판정기와 매개변수, 조기 이벤트 처리 방식, 클립 길이를 미리 지정한다. 방향은 배우 기준이다. 벤치 높이나 물체 위치 같은 장면 제약은 이번 언어 평가에서 제외한다.
- 시드는 17, 43, 97로 고정한다. 확산 100스텝, 후처리 켬, 외부 운동학 제약 없음, 동일 SOMA 모델 리비전을 쓴다. 지시별 재생 길이는 파일럿에서 결정한다. 해시가 있는 분할 목록, 판정 코드, 환경 잠금 파일, 모델 리비전과 개발용 ref 결과를 보관한다. 최종 세트 목록과 규칙도 이때 봉인하고 최종 평가 프로세스만 읽게 한다. 원본 캡션의 재배포 범위를 확인한 뒤 공유 범위를 정한다.
- 별도 파일럿에서 짧은 모션으로 좌우 부호, 단위, FPS, 메모리 측정 권한과 클립당 시간을 확인한다. 좌우 반전·시간 역순 합성 궤적으로 채점기가 기대한 플래그를 내는지도 검사한다. 평가 세트 동결은 이 작업 후 수행한다.

## 3. 프레임에서 점수 만들기

공식 SOMA NPZ의 월드 관절 좌표(미터), 프레임 순서, FPS로 채점한다. VRM 체형과 카메라 각도는 점수에 들어가지 않는다. 유형당 48개의 불리언 판정을 합쳐 `hits[arm][kind]`에 넣는다. 최소 대립쌍의 양쪽이 모두 성공한 비율도 진단용으로 기록한다. 이 수치는 개별 클립 성공률과 구분한다.

| 유형 | 판정기 정의 및 항목 예 |
| --- | --- |
| 1. 신체 좌우 | “왼손을 든다”는 지정 손목이 같은 쪽 어깨보다 10 cm 이상 높고 반대 손목은 반대 어깨 이하여야 한다. 두 조건이 0.2초 연속 성립해야 한다. 오른손 문장에서는 본 이름을 맞바꾼다. |
| 2. 회전 방향 | 모든 프레임에서 골반 전방축을 바닥에 투영한다. 프레임별 yaw를 unwrap하고 첫 yaw에 대한 마지막 구간 평균 변위를 구한다. 지정 방향 부호와 회전량을 모두 검사한다. 예컨대 90도 지시는 60~120도를 허용한다. |
| 3. 행동 순서 | 손 들기, 몸 낮추기, 회전 등 동결한 이벤트 판정기를 합성한다. 두 이벤트 모두 발생하고 첫 성립 프레임이 지시 순서대로 최소 0.2초 떨어져야 한다. 역순·동시·누락은 실패다. |
| 4. 자세 높이 | “몸을 낮춘 뒤 유지한다”와 “낮은 자세에서 일어난다”에는 처음과 끝 각 0.2초의 골반 높이 중앙값 차이를 사용한다. 지시 방향으로 0.20 m 이상 변하고 끝 자세를 마지막 0.2초 동안 허용 폭 0.05 m 이내로 유지해야 한다. |

위 예와 다른 동작을 쓰면 동일 수준으로 좌표·임계값·시간창을 항목 manifest에 넣는다. 0.2초 구간 길이는 `ceil(0.2 × fps)` 프레임이다. 조건별 프레임 임계값 조정은 허용하지 않는다.

`usable[arm]`은 다음 검사를 모두 통과한 클립 수다. ① 지시된 프레임 수·77관절·유한 좌표를 충족한다. ② 바닥 y=0 기준 좌우 발목/발끝 중 가장 낮은 관절이 −0.05 m 아래에 있는 프레임이 전체의 2% 이하다. ③ 각 발끝이 연속 0.2초 이상 바닥 0.06 m 이내에 머무는 각 최대 구간에서 수평 첫 위치로부터의 최대 변위가 0.10 m 이하다. 이 발 미끄러짐 검사는 정지 지지발을 기대하는 평가 동작에 한해 적용하며, 양발 모두 검사 구간이 없으면 해당 클립은 실패다. 평가 목록은 제자리 지지·회전·자세 변화로 구성하고 의도적인 발 끌기나 점프를 넣지 않는다. 이 점수는 기계적으로 측정한 품질이며, 뻣뻣한 동작도 통과할 수 있다. 세 조건의 동일 시드 영상을 익명 순서로 나란히 저장해 외관상 퇴화를 보고한다.

## 4. 학습과 반복

1. 원래 Kimodo 전처리와 LLM2Vec으로 영어 캡션의 실제 4096차원 출력을 캐시한다. EmbeddingGemma 2는 별도 호환 환경에서 텍스트 모드·BF16·768차원으로 시작한다. 영·한 양쪽에 적용할 문장 포맷, 풀링, 정규화와 리비전을 기록한다. 두 모델을 작업별로 순차 로드할 수 있다. Kimodo가 실제 받는 목표 벡터의 크기까지 보존한다. [Kimodo 기술 보고서](https://research.nvidia.com/labs/sil/projects/kimodo/assets/kimodo_tech_report.pdf) · [EmbeddingGemma 2 설정](https://huggingface.co/google/embeddinggemma-2)
2. 첫 후보는 동결한 EmbeddingGemma와 학습 가능한 `Linear(768,4096)`이다. 한국어 문장과 대응하는 영어 문장이 같은 영어 교사 벡터를 예측하도록 MSE로 학습한다. 체크포인트·전처리·훈련 데이터·코드 해시의 조합을 후보 ID로 쓴다. 임베딩 코사인, 노름 오차, 대립쌍 검색은 값싼 진단 지표다. 후보의 합격은 실제 모션으로 결정한다.
3. 개발 세트를 전부 채점한다. en과 ko가 함께 무너지면 입력 포맷과 목표 벡터의 노름을 먼저 확인하고, 필요하면 투영층 용량을 늘린다. ko에서만 좌우·순서 오류가 늘면 번역과 대립쌍을 점검한다. 데이터와 어댑터 개선 후에도 구분이 약하면 텍스트 백본 부분 미세조정을 시도한다. 매 회차는 한 가설과 한 변경을 기록한다. 같은 조건의 ref 결과는 재사용한다.
4. 개발 통과 시 체크포인트와 평가 코드를 동결한다. **최종 시험은 후보 하나에 한 번** 실시한다. 실패한 시험 결과로 v1을 다시 튜닝할 수 없다. 후속 연구를 하려면 새 시험 세트를 준비해 별도 실험 ID로 시작한다.

### Colab T4 어댑터 학습 파일럿

[Train_EmbeddingGemma2_Adapter_T4.ipynb](Train_EmbeddingGemma2_Adapter_T4.ipynb)의 기본 모드는 `train`이다. Colab 웹 UI에서 노트북을 열고 T4 런타임을 선택한 뒤, 아래 학습 입력 ZIP을 올리고 **모두 실행**을 한 번 누른다. 별도의 `smoke` 실행이나 MCP/CLI 연결은 필요 없다. `smoke`는 입력 없이 설치를 진단하는 선택 모드이며, 합성 교사로 만든 체크포인트는 모션 평가에 쓰지 않는다. 첫 실행에는 공개 EmbeddingGemma 2 체크포인트(약 1.5 GB)를 내려받지만, vision/audio 타워는 로드하지 않는다.

T4에는 네이티브 BF16이 없고 [EmbeddingGemma 2 모델 카드](https://huggingface.co/google/embeddinggemma-2/blob/f9972ac22e696a105c482202646979e33e4b5a1e/README.md)는 FP16을 사용하지 말라고 명시한다. 따라서 이 노트북은 **FP32 파일럿**으로 격리된다. `MODE='train'`도 v1 BF16 결과로 간주하지 않는다. v1의 BF16을 그대로 유지하려면 4090의 별도 호환 환경에서 학생 특징을 BF16으로 캐시하고 T4에는 특징과 교사 벡터만 보내는 단계를 별도로 마련하거나, 정밀도 변경을 새 실험 프로토콜에 명시해야 한다. v1의 RTX 4090 지연/메모리 Gate와 앱 내보내기 시험은 Colab 수치로 대체하지 않는다.

실제 파일럿에는 분할 누출 검사와 번역 검수를 마친 학습용 UTF-8 JSONL이 필요하다. 각 줄의 스키마는 `{"id":"clip-id","group_id":"clip-and-mirrors-group","split":"train","en":"Raise the left hand.","ko":"왼손을 든다."}`이다. 동일 원본·반전본·바꿔 쓴 문장·최소 대립쌍은 같은 `group_id`를 사용한다. 개발/시험 목록은 이 입력이나 Colab 환경에 넣지 않는다. BONES-SEED 접근 조건과 Colab 업로드가 허용되는지는 실제 자료를 사용하기 전에 확인한다.

저장소 루트에서 기존 RTX 4090 Kimodo 백엔드 환경으로 교사 캐시를 준비한다. 첫 실행 시 고정 리비전의 Meta Llama 3 가중치 접근 권한이 필요하지만 캐시가 이미 있으면 로컬에서 처리할 수 있다.

```powershell
& .\backend\.venv\Scripts\python.exe .\docs\experiment\cache_llm2vec_teacher.py <학습-JSONL-경로> <새-출력-디렉터리>
```

출력에서 `kimodo-train-input.zip` 하나만 Colab의 `/content`에 올린다. ZIP에는 `train.jsonl`, `targets.npz`, `teacher.json`만 있다. 노트북은 학습 전에 파일 목록과 SHA-256, 학습 분할, 행 수·ID 일치, 교사 벡터 모양과 유한값, T4 연결을 검사한다. 검사를 통과하면 중간 확인 없이 임베딩 생성과 어댑터 학습을 진행한다. `targets.npz`의 교사 벡터는 노름 정규화 없이 저장하며, 같은 교사 벡터를 각 EN/KO 쌍에 적용한다.

완료 후 Colab 파일 패널에서 `/content/kimodo-runs/t4-fp32-pilot-01/kimodo-result.zip` 하나를 내려받는다. ZIP에는 `adapter.safetensors`와 `run.json`이 들어 있다. 런타임이 도중에 종료되면 자동 재개하지 않으므로, 새 런타임에서 입력을 다시 올리고 실행한다. 이 파일럿은 모션 생성용 인코더 연결, 동결 평가 세트, 판정기 또는 v1 합격 판정을 아직 구현하지 않는다.

### 실행 비용과 증거

- `peak[arm]`은 독점 사용한 4090 한 장에서 모델 로드 시작부터 마지막 요청 완료까지 20 ms 간격으로 기록한 장치 전체 사용 메모리의 최대값(MiB, 올림)이다. Kimodo와 별도 인코더 프로세스 양쪽이 포함된다. 공통 유휴 상태에서 조건별 프로세스를 새로 시작하고 정밀도·오프로딩 정책·다른 GPU 프로세스를 기록한다. 각 평가 세트에서 동일 순서로 세 조건을 실행한다.
- `p95[arm]`은 평가 전 별도 프롬프트로 1회 예열 후, 요청 수락부터 세 파일 저장 완료까지 걸린 시간의 nearest-rank 95백분위(ms, 올림)다. 192개 요청을 동시성 1로 측정한다. 추론 중 텍스트 임베딩 캐시는 세 조건 모두 끄고, 학습용 교사 캐시와 모션 재생 캐시는 측정에서 배제한다. 원천 타이밍과 유휴 메모리도 함께 보관한다.
- `standalone`은 Llama 가중치·교사 서비스·교사 캐시에 접근할 수 없는 환경에서 신규 영·한 문장 생성이 모두 성공했음을 뜻한다. Gemma와 학습한 어댑터는 미리 제공한다. `exports`는 각 언어에서 새로 만든 테이크를 웹 UI에서 VRM으로 재생하고 세 포맷을 다시 읽어 FPS, 프레임 수, SOMA 골반 궤적을 확인한 결과다. FPS가 파일에 없으면 테이크 메타데이터를 쓴다. 궤적은 축·단위 변환 후 최대 절대 오차 1 mm까지 허용한다.
- `evidence`는 동결한 해시 일치, 데이터 분할 무결성, 모든 ID×시드×조건에 대한 로그, 전체 자원 측정과 재현 명령, 체크포인트 해시, 성공·실패 판정 근거와 비교 영상의 존재를 모두 검사해 산출한다. 모든 결과가 성공하면 실패 예시 개수 0을 기록한다. 생성 오류·NaN을 표본에서 삭제하거나 다른 시드로 대체하지 않는다. 후보 오류는 해당 클립의 이행·품질 실패로 채점하고 독립 실행이나 내보내기 자체가 깨지면 해당 플래그를 내린다. 측정 누락·환경 혼입처럼 비교 자체가 무효이면 `evidence=FALSE`다. 형식이 깨진 보고서는 판정기 입력 전에 무효 보고서로 변환한다.

## 5. 상태 전이와 검증

`Dev`의 유효한 회차마다 `Gate`를 평가한다. 통과하면 즉시 `Frozen`으로 간다. 미통과 시 7개 검사 묶음(영·한 각각 이행/품질/비용, 언어 차이)의 통과 개수를 먼저 비교하고, 동률이면 영·한 이행 성공 수의 합으로 개선을 판정한다. 최고 점수를 엄격하게 넘어야 개선이다. **3회 연속 개선 없음 또는 총 8회**면 `Stopped`로 마친다. 이 점수는 탐색 중단에만 쓴다. 점수가 높아도 어느 한 합격 조건을 만족하지 못하면 배포 후보가 될 수 없다.

`Frozen`에서는 동결한 후보만 최종 평가한다. 최종 `Gate=TRUE`는 `Accepted`, 유효한 결과의 기준 미달은 `Rejected`, 무효 증거는 `Blocked`다. `Blocked`이면 원인과 마지막 유효 체크포인트를 보고한다. 정전·재시작 때는 영속 로그에서 상태를 복원하고 미완료 요청만 같은 ID로 재개한다. 최종 결과 일부를 본 뒤 설정을 바꾸면 그 시험은 무효다. 유한 예산이 보장하는 것은 **판정에 도달하는 것**이며, 측정 전에는 성능 목표 달성을 보장할 수 없다.

각 회차에 설정·비교표·판정기 출력·실패 유형·다음 가설을 남긴다. 최종 보고서에는 원시 성공 수/분모, 기준선과의 %p 차이, 비용 비율, 통과하지 못한 식, 재현 명령과 체크포인트를 기재한다. 종료 상태가 `Accepted`일 때만 후보를 앱에서 선택 가능하게 릴리스한다.

### TLA+ 실행

이 디렉터리에서 아래 명령을 실행한다. [EncoderTrial.cfg](EncoderTrial.cfg)의 `Examples`는 경계값·실패·증거 누락을 포함한 **모델 검사 전용** 입력이다. 실제 실험 평가기는 후보 ID와 동결한 manifest를 확인하고 원시 로그를 집계해 `Gate`와 같은 정수식을 계산한다. 테스트가 개발 결과를 읽거나 동결 후보를 바꿔치기하는지는 파일 해시와 평가 프로세스가 검증한다.

```sh
java -cp /path/to/tla2tools.jar tlc2.TLC -workers 2 EncoderTrial.tla
```

TLC 2.19에서 예시 보고서로 550개 고유 상태를 검사했다. 회차·시험 횟수 상한, 동결한 회차만 시험하는 조건, 합격 판정의 건전성, 경계값 예시, 공정한 실행에서의 종료 속성이 통과했다. 예컨대 ref 지연이 1000 ms이면 후보 1200 ms는 허용하고 1201 ms는 거부한다. 실제 GPU 점수는 이 모델 검사 결과와 별도로 보고한다.
