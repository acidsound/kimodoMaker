# Kimodo v2 모션 품질 개선 Implementation Plan

> 재개할 때 이 문서의 ‘재개 카드’부터 읽고, 검사한 산출물로만 완료 칸을 갱신한다. 새 세션은 종전 대화에 의존하지 않는다.

**목표 (사용자 결정):** 현재 Kimodo Maker에서 실사용 프롬프트가 만드는 모션의 지시 이행과 실제 품질을 개선한다. 먼저 영어 원문으로 기존 모델보다 나은 생성 결과를 입증한다. 한국어 지원과 가중치·VRAM·지연 최적화는 그 결과를 기준으로 별도 검증하는 후속 과제다. Llama 제거·인코더 교체·본학습 자체는 이번 단계의 완료 요건이 아니다.

**설계:** 개선 대상은 프롬프트 → TextEncoder → 모션 생성기에 전달되는 텍스트 조건이다. 첫 쌍대 실험에서는 공식 영어 인코더의 원래 조건과 의미 강조 조건만 바꾼다. 생성기·시드·길이·스텝·제약·후처리는 고정한다. 설정 튜닝, 렌더러 수정, 임베딩 코사인 상승만으로 인코더 개선을 선언하지 않는다. 원본 SOMA와 실제 VRM 재생을 별도로 검사하고, 독립 자연 프롬프트에서 지시 이행과 시각 품질이 같이 개선된 경우에만 출시한다. v1은 읽기 전용이다.

**환경과 모델 결정:** Windows 11, RTX 4090, 공식 Kimodo/SOMA + LLM2Vec을 품질 기준선으로 유지한다. 공식 경로는 4096차원 LLM2Vec 조건 토큰을 사용한다.[3] EmbeddingGemma 2는 폐기하지 않되 품질 개선 주경로에서는 보류하고, v1 체크포인트는 회귀 비교에만 사용한다. 후속 경량화에서 다시 비교한다면 BF16 텍스트 모드의 포맷을 고정한다.[4]

### 첫 실험에서 답할 질문과 분기

1. 실제 앱에서 명시한 신체 부위가 목표에 도달하는가? 예: `raise right foot beside head`는 오른발–머리의 프레임별 거리를 좌측과 함께 본다. 뷰어에서 뼈가 움직였다는 사실은 이 지시의 성공이 아니다. 출처에 성공 라벨이 없으면 수동 라벨을 발명하지 않는다.
2. 공식 경로의 반복 편차를 측정한 뒤 텍스트 조건만 바꾸면 반대 방향·반대 사지 등 최소대립 지시를 더 잘 구별하는가? 기준선과 후보를 같은 프롬프트/시드로 전량 보관한다. 지시하지 않은 다른 사지까지 움직이는 양과 악화 사례도 보존한다. 추론 경로와 가중치 학습을 구분한다.
3. 이득이 없으면 후보를 배포하지 않는다. 약점이 방향·좌우에 국한되면 해당 의미만 겨냥하는 다음 후보와 손대지 않은 입력에서의 항등 대조를 사용한다. 접촉·자연스러움만 실패하면 텍스트 이해로 귀속하지 않는다. 파일럿에서 이긴 경우에도 봉인 시험을 열기 전에 독립 dev와 기본 앱 대비 부작용을 평가한다. 영어 실사용 분포와 다른 캡션 자료는 보조 근거로 표기한다. 낮은 점수 뒤 목표·평가지표·시드를 재정의하지 않는다.

### 실행 산출물과 복구 규약 (P1.4 구현 대상)

```text
v2-encoder-4090/<experiment_id>/
  lock.json              # 프로토콜·입력·시드·코드·모델·환경 해시
  progress.json          # phase / next / last_verified / exact argv / blocker
  provenance.json        # 출처·허용범위·분할·환경(토큰/원문 비공개)
  diagnostics/           # v1 회귀, ref/oracle/판정기 파일럿
  dev/<candidate_id>/    # config, checkpoints, per-arm journals, reports, done.json
  private/               # 리뷰 키·단일 시험 상태·공개 여부, 학습 쪽 접근 불가
```

- 쓰기 전 `experiment_id`, 단계, 후보/프로토콜 해시, 명령·작업 디렉터리, 선행 증거, 예산을 기록한다. 단일 작성자 잠금에서 임시 파일을 검증·flush하고 동일 볼륨에서 원자 교체한다. 완료는 기대 키 전체와 산출물 해시를 확인한 `done.json`이 있어야 인정한다. 커밋 마커 없이 남은 파일은 검증된 완료로 치지 않고 격리/복구 규칙을 적용한다. 중간 로그 또는 ckpt를 덮어써서 고치지 않는다.
- 키는 `experiment_id / stage / candidate_id / arm / prompt_id / seed` 및 `protocol_sha256`. 판정은 `report_sha256`과 선택 후보에 묶는다. 재적용은 no-op, 다른 후보·잠금·측정 설정은 같은 런에 섞지 않는다. 최종 시험 ID를 최초 실행 전에 기록하고 이어하기는 동일 ID·동일 후보만 허용한다. 두 번째 결과 발행 금지.
- 학습은 epoch 경계(파일럿에서 최대 손실 작업 시간 확인, 한 epoch가 너무 길면 배치 샤드 경계)마다 모델·옵티마이저·스케줄러·epoch/샘플 순서·CPU/CUDA RNG·입력/환경 해시를 저장한다. 특징 캐시도 샤드 ID·순서·해시로 검증 후 확정한다. 재시작 대비 안전 보관소는 scratch 밖이며, 프로젝트 외 백업은 허용된 위치/범위만 사용한다. 코드가 untracked인 상태에서는 실행 스냅샷/해시를 남겨 HEAD로 코드가 복원된다고 가정하지 않는다.
- **동작 재개와 비용 측정은 분리.** 여러 세션에서 재개된 생성 결과는 누락·중복 없는 모션 증거로 사용한다. 최종 비용은 정상 상태의 동일 GPU에서 arm별 새 프로세스→동일 예열→동시성 1 전체 측정이 완결된 세션만 사용. 끊긴 세션은 보관하고 비용 측정만 처음부터 새 세션으로 수행한다. 표본 중 일부만 뽑거나 최적 시간끼리 합치지 않는다.

## P2 — 후보를 보기 전에 평가와 데이터 동결

- [ ] **P2.1 범위/모집단.** 영어 실사용 문장을 수집한다. 단일 주동작의 전신/이동, 자세/바닥 동작, 방향/회전, 팔다리/좌우를 초기 층으로 제안한다. 두 동작의 순서 준수는 기존 사용자 결정대로 이번 인수 시험 밖이다. 알려진 실패와 성공 예제는 회귀용; 자연 dev/test는 사전에 정의한 앱 사용례에서 결과를 모르는 문장을 독립 모집한다. 프롬프트별 꼭 맞아야 할 동작·방향·속도/강도와 허용 변형을 고정한다. 한국어 대립 번역은 지금의 병목이 아니다.
- [ ] **P2.2 분할·권한.** `train`(학습 경로가 필요할 때만), `pilot`, `regression`, `dev`, `sealed-test` 분리. 같은 원본·테이크·반전본·번역·바꿔쓰기·최소 대립쌍은 한 그룹. 문자열과 의미상 누출을 모두 검사한다. 17개 v1 자연 프롬프트와 동계열은 회귀 전용. BONES-SEED 쓸 때는 확보한 허용 범위와 원본 리비전/파일 해시를 기록하고 데이터 제공 조건을 따른다.[1][2] v004 CSV는 stdlib로 자연 캡션·테이크·반전·모션 경로를 감사할 수 있다. 합성 템플릿 대량 복제는 자연 자료를 대체하지 않는다. 실제 궤적을 소비하는 학습/평가가 선택되면 필요한 SOMA 형식의 원본을 미리 받고 소수 모션의 캡션 정렬·좌표계·스켈레톤·FPS·길이·미러 변환을 검증한다. 다른 포맷/전체 스냅샷은 전제하지 않는다.
- [ ] **P2.3 판정기 먼저.** 사람이 채점할 자연 동작마다 필수 동작·방향·품질에 관찰 가능한 기준을 부여하고 독립 리뷰→불일치 중재를 고정한다. 사람 판정이 1차이고 운동학은 검증된 유형의 보조/품질 검사다. v1의 정지 지지발 규칙을 구르기·도약 등에도 일괄 적용하지 않는다. 두 리뷰어 일치율의 최소 기준(제안 85%)과 반례 통제 클립 통과 요건을 파일럿 이전에 승인·기록한다. `성공/실패/측정 무효`를 구분한다. 생성 오류는 후보 실패, 로그 누락·GPU 혼입은 비교 무효. 팔 반전·회전량 미달 등 negative control로 채점기 민감도를 확인한다.
- [ ] **P2.4 기준선 및 인수 규약 사전등록.** 원본 앱 설정을 제품 비교 기준으로 고정한다. 학습을 시험한다면 pilot에서 고른 가장 좋은 무학습 설정도 독립 기준선으로 동결한다. 초기 규모안: dev/test 각 64개 프롬프트 그룹 이상, 층별 균형, 공통 시드 17/43/97. 개수·층 가중치·판정 단위·최소 실질 개선폭·허용 퇴화·자원 한도·불확실성 처리 규칙은 후보 확인 전 확정. ref의 점수가 낮은 것 자체는 무효 사유가 아니다. 재현 실패, 판정 통제 실패, 로그 불완전, 오염은 무효 사유다. 원본이 실패한 문장을 점수에 맞춰 빼지 않는다. 봉인 시험은 결과와 arm을 가린 독립 평가로 한다.
- [ ] **P2.5 동결.** `docs/experiment/v2_gate.py` 및 대응 테스트(제안 경로)에 사전등록된 실제 분모·층·정수 경계·누락 체크를 구현한다. v1 `EncoderTrial.tla`, `v1_score.py`를 편집하거나 그대로 적용하지 않는다. 시험은 분리된 사용자/평가 프로세스만 원문·키에 접근. dev에는 시험 상태/해시만 제공. 학습/캐시/검색 인덱스가 시험 원문을 소비하지 않는 부정 테스트 수행. 시험 기준을 바꾸려면 새 실험 ID와 새 봉인 시험을 사용한다.

**인수 기준안 — 해시 잠금 전까지 제안:** 영어 실사용 홀드아웃에서 원본 앱 대비 ‘지시 이행과 시각 품질을 모두 충족한 클립’ 비율이 사전등록된 최소폭 이상 증가해야 한다. 이행률과 품질을 별도 보고하고 전체·핵심 동작군/기존 성공군에서 사전 허용폭을 넘는 퇴화가 없어야 한다. 학습 후보는 동결한 무학습 대조 대비 추가 이득도 보여야 채택한다. 같은 프롬프트/시드의 블라인드 판정, VRM 실제 재생, JSON/BVH/NPZ 무결성, 장치·지연·메모리 예산을 기록한다. 한국어·Llama 제거·v1 비용 절감 비율은 이번 품질 gate로 재사용하지 않는다. 원본 대비 차이와 불확실성을 프롬프트 그룹 단위로 제시하고, 세 시드를 독립 표본 세 개로 취급하지 않는다.

## P3 — 짧은 대조 실험으로 경로 선택

- [ ] **P3.1 학습 없는 비교부터.** 공식 Kimodo+LLM2Vec을 유지하고 pilot의 성공/실패 대표군에서 기본 앱 → 의도 보존 프롬프트 정리 → 텍스트 CFG 또는 후처리 설정을 한 번에 하나씩 바꿔 동일 시드로 대조한다. 먼저 NPZ와 VRM 차이를 확인하고, 시간/샘플 선택 예산을 고정한다. 여러 샘플을 만들 경우 실제 요청에서도 사용할 고정 선택법과 지연까지 비교하고 좋은 시드만 골라 점수를 올리지 않는다. 무학습 후보가 dev/test 인수 기준을 충족하면 가중치 학습 없이 종료 가능하다.
- [ ] **P3.2 학습 재개 실증 (학습 경로만).** P3.3에서 정한 대상 모델의 학습 진입점(새 코드가 필요하면 `docs/experiment/v2_train.py`)에서 작은 실제 데이터 샤드로 중단 없는 실행과 중단→재개를 비교한다. 샘플 순서·최종 스텝·메트릭·체크포인트 해시가 일치하거나, 사전에 정한 비결정성 허용 범위와 사유가 충족되어야 한다. 키 충돌·입력 해시 변경·중복 스텝은 거부. 중단 지점/명령/결과는 `diagnostics/restart-drill.json`에 남긴다.
- [ ] **P3.3 가설별 학습 파일럿.** 원본 프롬프트의 의미 보존 정리만으로 좋아지면 텍스트 처리부터, 같은 지시를 알아들어도 원본 NPZ에서 접촉·동역학 등이 무너지면 생성기/후처리 쪽부터 검증한다. 학습이 필요하면 실패 유형에 대응하는 표적·손실과 데이터 종류를 먼저 정의한다. 예: 생성 후보의 실제 선호로 재순위화하면 기록된 선호 라벨이 필요하고, 녹화 궤적을 직접 감독하면 정렬된 SOMA 모션이 필요하다. 생성기 미세조정은 실제 학습 인터페이스와 작은 배치의 GPU 메모리·체크포인트 호환성을 검증한 뒤 선택한다. 교사 텍스트 MSE만 반복해 품질 향상을 가정하지 않는다. 임베딩 압축은 개선된 영어 기준선을 확보한 뒤 별도 경로에서 비열화 검증으로 다룬다.
- [ ] **P3.4 자원과 중단 규칙.** 파일럿 시작 전 시간·디스크·후보 비교 예산을 `lock.json`에 적는다(초기 제안: 대조 4개, 실제 모션에 올릴 신규 후보 최대 2개). 모션 지표가 동반 개선하지 않으면 epoch/모델만 바꿔 반복하지 않고 위 분기로 돌아간다. 예산을 넘으면 마지막 검증 결과·다음 가장 값싼 반증 실험·추가 비용을 기록하고 멈춘다. `Blocked/Stopped`는 근거와 다음 행동을 남기는 상태이지 합격은 아니다.

**본학습 시작 조건:** (1) 원본 영어 품질 실패를 동일 설정으로 재현, (2) 블라인드 판정과 독립 분할·기준선 동결, (3) 무학습 대조 수행 및 추가 학습이 겨냥할 실패 유형 확인, (4) 해당 데이터·손실에서 소형 실제 모션 비교가 무학습 기준을 이김, (5) 중단/재개 실증과 GPU·시간·디스크 예산 확정. 하나라도 없으면 장기 학습을 시작하지 않는다.

## P4 — 개발 통과, 최종 시험, 배포

- [ ] **P4.1 Dev 전체 검사.** 기본 앱, 사전 선택 대조(해당 시), 후보의 정확한 기대 키·블라인드 리뷰·운동학·비용을 출력한다. 후보 ID는 가중치 또는 추론 설정·전처리·데이터·코드·환경을 묶는다. `dev-report.json` 및 원자료 참조를 남긴다.
- [ ] **P4.2 단일 최종 시험.** `Frozen` 후보 하나를 봉인 평가자가 실행한다. 읽기/결과 공개 감사 로그, 자동 검증, candidate/protocol/report 해시를 보존한다. 중단은 같은 시험 ID의 재개만 허용. `Accepted`, `Rejected`, `Blocked`를 구분하고 시험 실패를 보고 다시 튜닝하지 않는다. 최종 시험을 다시 하려면 새 독립 세트와 실험 ID가 필요하다.
- [ ] **P4.3 배포.** `Accepted` 증명과 해시가 일치하는 가중치 또는 추론 설정만 출시 경로에서 로드하는 테스트, 승인 없는 체크포인트/바꿔치기 거부, 신규 영어 테이크의 VRM 움직임과 JSON/BVH/NPZ 프레임·FPS·골반 궤적 대조를 수행한다. 기존 공식 경로로 되돌리기를 유지한다. `v1_export_check.py`의 과거 증거를 새 후보에 물려주지 않는다. `docs/experiment/REPORT-v2.md`는 실제 결과가 나온 뒤 작성한다.
